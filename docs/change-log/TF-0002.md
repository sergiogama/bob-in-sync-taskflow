# TF-0002

## Change
Added a self-service password reset feature. Users can request a reset token via a new "Forgot password?" flow on the login page. The token is returned in the API response (no email infrastructure — an admin shares it with the user). The user enters the token and a new password on the `/reset-password` page to complete the reset. Tokens expire after 1 hour and are single-use.

## Confirmed Rules
- Reset token returned directly in API response (no SMTP — out of scope)
- Any active account holder can request a reset using their email address
- Tokens expire after 1 hour
- New password minimum length: 8 characters
- Tokens are invalidated after first successful use

## Security hardening follow-up

The original self-service token issuance described above was superseded by a Manager-mediated flow:

- public requests no longer reveal whether an account exists or return reset tokens;
- only authenticated Managers can issue a reset token from the Users page;
- the database stores a SHA-256 token hash instead of the usable token;
- password update and token consumption are transactional;
- a successful reset revokes the user's existing sessions;
- validation now covers 13 passing backend tests plus a successful production build.
